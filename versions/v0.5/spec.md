## 1. 概要

### 1.1 システム概要

本システムは、Javaコードに対して「判断系コーディング規約」（意味的・主観的でLint等では検出しづらい規約）の準拠性をLLMを使って点検するオーディターです。

### 1.2 対象ユーザー

- コードレビュー担当者
- 品質管理担当者
- 開発リーダー

### 1.3 システム構成

```
┌─────────────────┐     HTTP/REST      ┌─────────────────┐
│   フロントエンド   │ ◄──────────────► │   バックエンド    │
│  (React + Vite)  │                   │   (FastAPI)     │
└─────────────────┘                   └────────┬────────┘
                                               │
                    ┌──────────────────────────┼──────────────────────────┐
                    │                          │                          │
              ┌─────▼─────┐            ┌───────▼───────┐          ┌───────▼───────┐
              │  LLM API   │            │  静的解析ツール  │          │ 変換ライブラリ │
              │ (Bedrock/  │            │ (Checkstyle/   │          │ (excel2md/    │
              │  Anthropic/│            │  PMD/Ruff等)   │          │  markitdown)  │
              │  OpenAI)   │            └───────────────┘          └───────────────┘
              └───────────┘
```

## 2. 機能要件

### 2.1 機能一覧

| No | 機能名 | 概要 | 優先度 |
|----|--------|------|--------|
| F-01 | ファイルアップロード | 規約ファイル・コードファイルのアップロード | 必須 |
| F-02 | Excel変換 | ExcelファイルをMarkdown形式に変換 | 必須 |
| F-03 | 行番号付与 | コードファイルに行番号を付与 | 必須 |
| F-04 | AI監査実行 | LLMによるコーディング規約準拠性チェック | 必須 |
| F-05 | 静的解析実行 | Checkstyle/PMD等による静的コード解析 | オプション |
| F-06 | 結果表示 | 監査結果の表示・判定 | 必須 |
| F-07 | レポート出力 | Markdown/ZIP形式でのレポートダウンロード | 必須 |
| F-08 | 設定管理 | LLM設定・システムプロンプト管理 | 必須 |
| F-09 | 設定ファイル生成 | reviewer-config.mdの生成ツール | オプション |

### 2.2 機能詳細

#### F-01: ファイルアップロード

| 項目 | 内容 |
|------|------|
| 対応形式（規約） | Excel (.xlsx, .xls), Markdown (.md) |
| 対応形式（コード） | Java (.java), Python (.py), その他テキストファイル |
| ファイルサイズ上限 | 規約: 10MB, コード: 5MB |
| アップロード方法 | ドラッグ&ドロップ または ファイル選択ダイアログ |
| ファイル再選択 | プログラムファイルを再選択した場合、既存のファイル一覧を新しい選択結果で置換する |

#### F-02: Excel変換

| 項目 | 内容 |
|------|------|
| 変換ツール | MarkItDown, excel2md, excel2md-mermaid |
| 入力形式 | Excel (.xlsx, .xls) |
| 出力形式 | Markdown (.md) |
| 特殊対応 | AIオーディター形式Excelのスプレッドシート表示 |

##### F-02-A: AIオーディター形式Excel

###### ファイル構造

| シート | 内容 | 必須 |
|--------|------|------|
| 1シート目 | コーディング規約一覧 | ○ |
| 2シート目以降 | 規約ごとの詳細説明 | - |

- サンプルファイル: `docs/ai-auditor-format/20260121AIオーディター形式サンプルコーディング規約.xlsx`

###### 画面表示仕様

| 項目 | 内容 |
|------|------|
| 表示ライブラリ | Tabulator |
| 表示形式 | スプレッドシート形式（Excel全体を表示） |
| 編集機能 | なし（読み取り専用） |
| シート切替 | タブによるシート切り替え |
| シートリンク | セル内の詳細シートリンクをクリックで該当タブに切り替え |

###### 規約選択機能

| 項目 | 内容 |
|------|------|
| 選択対象 | 1シート目のコーディング規約各行 |
| 初期状態 | 全規約選択状態 |
| 選択UI | チェックボックスによる行選択 |

###### Markdown変換ロジック

| 対象 | 変換ルール |
|------|------------|
| 1シート目（規約一覧） | 選択された規約のみMarkdownに含める |
| 2シート目以降（詳細） | 選択された規約にリンクされている詳細シートのみ含める |
| 複数規約が同一詳細シートにリンク | いずれか1つでも選択されていれば詳細シートを含める |

#### F-03: 行番号付与

| 項目 | 内容 |
|------|------|
| 形式 | 4桁右寄せ + コロン + 半角スペース |
| 例 | `   1: public class Sample {` |
| 文字エンコーディング | UTF-8, Shift_JIS（自動判定） |

#### F-04: AI監査実行

| 項目 | 内容 |
|------|------|
| 実行回数 | 2回（一貫性確認のため） |
| 対応LLMプロバイダー | AWS Bedrock, Anthropic, OpenAI |
| タイムアウト | 5分 |
| 入力構成 | システムプロンプト + 規約 + コード + 静的解析結果（任意） |

#### F-05: 静的解析実行

| 項目 | 内容 |
|------|------|
| Java用ツール | Checkstyle, PMD |
| Python用ツール | Ruff, Flake8, Pylint |
| 実行タイミング | AI監査前（オプション） |
| 結果連携 | 静的解析サマリーをLLMコンテキストに含める |
| Windows対応 | `.bat/.cmd` 形式のツールを `cmd /c` 経由で安全に実行（`shell=True` 不使用） |
| エンコーディング | ツール出力を UTF-8 → CP932 → デフォルト → replace の順でフォールバックデコード |
| ファイルエンコーディング変換 | 解析対象ファイルが CP932 の場合、一時ファイルに UTF-8 で書き戻してからツールに渡す |

#### F-06: 結果表示

| 項目 | 内容 |
|------|------|
| 判定種別 | OK, 要確認（Warning）, NG |
| 表示形式 | タブ切り替え（静的解析 / 監査#1 / 監査#2） |
| 判定ロジック | LLM出力から「OK」「NG」「要確認」キーワードを検出 |

#### F-07: レポート出力

| 項目 | 内容 |
|------|------|
| 個別ダウンロード | Markdownレポート |
| 一括ダウンロード | ZIP（レポート + コード + メタデータ） |
| クリップボード | コピー機能 |

#### F-08: 設定管理

| 項目 | 内容 |
|------|------|
| LLM設定 | プロバイダー, モデル, 認証情報, 最大トークン |
| システムプロンプト | プリセット管理（役割/目的/フォーマット/注意事項） |
| 設計書種別 | カスタム種別の追加・編集・削除 |
| 永続化 | ブラウザのlocalStorage |

#### F-09: 設定ファイル生成

| 項目 | 内容 |
|------|------|
| 出力形式 | reviewer-config.md |
| 設定項目 | LLM設定, 設計書種別, システムプロンプトプリセット |

## 8. 制約事項・前提条件

### 8.1 制約事項

1. LLMの判定結果は参考情報であり、最終判断は人間が行う必要がある
2. 判断系ルールは絶対的な判定が困難なため、誤検出が発生する可能性がある
3. 大規模ファイルの処理はトークン制限により分割が必要な場合がある
4. 静的解析ツールは別途インストールが必要

### 8.2 前提条件

1. 対応OS: macOS, Linux, Windows（Windows では静的解析ツールが `.bat/.cmd` 形式で提供される場合がある）
2. Node.js 20.0.0以上がインストールされていること
3. Python 3.11以上がインストールされていること
4. LLMプロバイダーの認証情報を保有していること
5. ネットワーク接続が利用可能であること
