# v0.5.1 Path Traversal 脆弱性修正 計画書（2026-05-07）

## 目的

[Issue #19](https://github.com/elvezjp/coding-policy-ai-auditor/issues/19) で指摘された `_safe_relative_path` メソッドの Path Traversal 脆弱性を、**v0.5.1 として新規ディレクトリで修正リリース**する。過去バージョン（v0.3, v0.4）は README の Dependabot Alert Policy に準じて修正対象外とする。

## 対象 Issue

| 番号 | タイトル | 種別 |
|------|---------|------|
| [Issue #19](https://github.com/elvezjp/coding-policy-ai-auditor/issues/19) | [Security] Path Traversal: `_safe_relative_path` の fallback に欠陥があり任意ファイル書き込みが可能 | security / fix |

## 前提・経緯

- v0.5.0 の `versions/v0.5/backend/app/services/static_analysis/base.py` 内 `_safe_relative_path` の fallback ロジックに欠陥
- `..` を含むパスを検知した際、fallback で同じ `name` フィールドをそのまま返すため、Path Traversal が成立
- 攻撃シナリオ: `POST /api/static-analysis/analyze` に `"name": "../../../tmp/evil.py"` を送ることで、tmpdir 外への任意ファイル書き込みが可能（認証不要、`.py` / `.java` 等の許可拡張子で動作）
- 深刻度: **HIGH**（信頼度 9/10）
- 過去バージョン（v0.3, v0.4）にも同一の問題があるが、本リポジトリの方針（README の Dependabot Alert Policy に準ずる）に従い修正対象外とする

## 方針

### バージョニング

- v0.5 ディレクトリは現行のまま残し、新規に **`versions/v0.5.1/`** を作成して修正版を提供する
- v0.5.1 は v0.5 を丸ごと複製したうえで、`base.py` のみを修正する

### 修正方針（多層防御）

Issue 中で提示された 2 つの修正案を **両方** 適用する。

#### 方法 1: `_safe_relative_path` の fallback でディレクトリ部分を除去

```python
def _safe_relative_path(self, file_data: dict[str, str]) -> Path:
    file_path = file_data.get("path") or file_data.get("name", "")
    candidate = Path(file_path)
    if candidate.is_absolute() or ".." in candidate.parts:
        name_only = Path(file_data.get("name", "")).name
        return Path(name_only) if name_only else Path("unknown_file")
    return candidate
```

#### 方法 2: `_create_temp_files` で resolve 後の境界チェック

```python
resolved = target_path.resolve()
tmpdir_resolved = Path(tmpdir).resolve()
if not resolved.is_relative_to(tmpdir_resolved):
    raise ValueError(f"Path traversal detected: {target_path}")
```

### 試験項目表

本修正の妥当性確認（Path Traversal が実際に防御されること）に加え、修正による既存機能への影響がないこと（静的解析実行・ファイル名処理・AI 監査の全体フロー）を確認する。

| 観点 | 影響 |
|------|------|
| API 仕様 | 変更なし（不正パスは従来 silent fallback → **明示的に拒否 or sanitize**） |

| 旧バージョン互換 | v0.5 はそのまま残置、利用者は v0.5.1 へ切り替えが必要 |
